# 淡彩极简风格指南

上游 scholia 默认配色偏「重」（饱和蓝 + 粗竖线 + 多处色块），适合当教材；
这份笔记的目标是**长时间阅读不累、重点一眼可见**，所以要往回减。

## 1. 三条原则

1. **正文是主角**：绝大多数篇幅是接近黑的普通段落，一眼扫过去只有黑字。
2. **强调靠行内**：需要提示时给那句话加淡色或加粗，不给它一个框。
   视觉负担：行内淡色 ≪ 底色块 ≪ 带竖线的色块。
3. **方框只换来编号和回指**：只有当内容真的需要被 `@label` 引用、或需要
   「这个结论是整章骨架」时，才动用 `definition` / `theorem` 方框。

## 2. 默认配色（`prelude.typ` 的 `soft-palette`）

**按内容类型分色相**，不是随便挑四个好看的颜色。逻辑固定如下，全篇不变
（色值与对比度见 [`typography-spec.md`](typography-spec.md) §7）：

| role | 语义 | 覆盖的内容 |
|---|---|---|
| `ink` | 正文 | 普通段落（主体） |
| `thm` | 蓝 · 结论推理 | theorem lemma proposition corollary conjecture claim · `proof` · qed 方块 · `@label` 回指 |
| `def` | 青绿 · 定义术语 | definition axiom assumption notation · `remark` · `mark-key` 术语 · `keyword` · `label-it` 标签 |
| `eg` | 琥珀 · 例子练习 | `example` · `yourturn` · `TODO` 填空缺口 · `workspace` |
| `warn` | 紫 · 易错警示 | `warn[…]`（本 skill 扩展，行内不加框） |
| `muted` | 灰 · 次要 | 页码 · `recall`/`sidenote` 边注 · `aside` |
| `fillin` | 灰 | 填空线 —— **留给读者写**的地方，刻意不用 `ink` |
| `hairline` / `rule` | 结构线 | `divider` · 标题横线 |
| `bg` | 纸白 | — |

分组依据是**内容之间的关系**，不是色相好不好看：

- 蓝 / 青绿 / 琥珀对应「推理—定义—应用」这条自然链条，读者一眼能建立预期。
- `keyword` 和 `tag` 归入青绿（术语和出处同属「定义」这一层），
  这样全篇只有四个强调色相，不会因为多出第五个色而变乱。
- `warn` 是唯一的第四色相，因为它承担的是「反例」语义——和前三类正交，
  不会误读成另一种内容类型。
- `remark` 归青绿：scholia 原生就把它渲染成定义族的斜体，保持一致。

调色只改 `zju_lecture/prelude.typ` 的 `soft-palette`（唯一权威副本），
再跑 `tools/sync_palette.py` 与 `tools/sync_skill_assets.py`；不要手改生成副本。
`warn` 是**扩展键**，scholia 原生只用 `thm`/`def`/`eg`/`tag`/`keyword`，
多余键无害（已实测编译通过）。

### 「等权」是这套配色好看的关键

四个强调色的对比度与「极差 ≤ 1.2」的量化口径见
[`typography-spec.md`](typography-spec.md) §7.3。改色时按那里的公式重算，
不要靠眼睛判断。

### 淡，但不能淡到看不见

这套色比上游**低一档饱和度**，但**没有**低到「性冷淡」。实测对比过三档：

| 档位 | thm | 观感 |
|---|---|---|
| 上游默认 | `#2F5EA8` | 偏重，作为教材可以，作为笔记太抢 |
| **本 skill 默认** | `#33609B` | 沉静但一眼可读 —— 推荐 |
| 过淡（踩过的坑） | `#7C8DB5` | 强调文字几乎消失，整页发灰，**不要用** |

判定标准（用对比度，不要靠眼睛）：

1. **算 WCAG 对比度**：强调文字 vs `bg`，**≥ 4.5:1**（AA 正文级）。
   默认 `#33609B` vs `#FDFDFB` = **6.27:1**，通过；
   被否掉的 `#7C8DB5` = **3.26:1**，不达标——这就是它「太淡」的量化原因。
2. **四个强调色的对比度极差 ≤ 1.2**，见上一节的「等权」说明。
3. **彩度可以降，亮度差不能降太多**。`#33609B` 与上游 `#2F5EA8` 亮度接近，
   差别只在彩度；`#7C8DB5` 两头都降，强调就消失了。
4. **色块底色要一起看**。`tint()` 把强调色按 9% 混向纸白，强调色一变淡，
   `definition`/`theorem` 的块底色会一起褪成灰白，方框区分度随之消失。
   所以调色时不能只盯行内文字。

速查：想再沉稳一点，把 `thm` 往 `#2F5EA8` 靠；想更淡，**不要低于 `#4A6FA5`**，
且四个色要同步调、保持等权。

约束：**正文色保持接近黑**、次要色保持灰；彩度只降一档，不降两档。

### 想换一整套色相时

保持三条不变，色相可以整套换：

1. `ink` 仍是接近黑的低彩度色（它是主体，占了绝大部分篇幅）。
2. `muted` / `hairline` 仍是中性灰（它们不参与语义分类）。
3. 四个强调色：色相要**两两可辨**（蓝 / 青绿 / 琥珀 / 紫 在色相环上隔得开），
   对比度要**等权**（极差 ≤ 1.2），且每色都 ≥ 4.5:1。
   改完算一遍对比度，渲染看一眼——只看数字可能被两个相近色相骗过。

## 3. 视觉预算（每节）

**权威口径在 [`format-spec.md`](format-spec.md) §2.2**（每节框合计 ≤ 2、直觉块 1、
练习块 1、边注 1～2、行内强调 2～3）。本节不再重复那张表；工具按 format-spec 的
口径统计，超预算时点名是第几节、超了几个，但**不会自动降级**——降级是内容判断。

## 4. 强调手段的降级顺序

写内容时遇到「这句要突出」，按这个顺序往下选，选到第一个够用的就停：

1. `#mark-key[术语]` —— 粗体 + 淡青（用于术语、关键名词）
2. `#accent[句子]` —— 只变色（用于关键结论、转折）
3. `*斜体*` —— 纯排版强调，不依赖颜色
4. `#whisper[补充]` —— 行内淡色，用于补充说明
5. `#aside[旁注]` —— 灰色小字 + 小一号，弱化信息
6. `#divider` —— 段落切分
7. `#note[…]` —— 带底色块，整节最多一个
8. `#theorem` / `#definition` 方框 —— 只为编号与回指

绝大多数「强调」需求在第 1～2 级就能满足，别一路降到 8。

`#warn[…]`（紫色）是第 3 级的加强版：用于「易错点」这类必须被看见但不必占版面的内容，
刻意做成行内而不加方框，所以它**不占视觉预算**。

带命名参数时**必须用圆括号**：`#accent([内容], strong: true)`。
写成 `#accent[内容, strong: true)` 会报 `unclosed delimiter`。

## 5. prelude 提供的五个助手

```typst
#mark-key[特征值]                            // 粗体 + 青绿（术语·定义族）
#accent([这句话是结论])                       // 蓝色（结论族）
#accent([这句更重], strong: true)            // 变色 + 加粗
#accent([定义族颜色], tone: "def")           // 青绿
#accent([例题提示], tone: "eg")              // 琥珀
#warn[易错点：别漏掉边界条件]                 // 粗体 + 紫，行内不加框
#aside[弱化旁注]                              // 灰色小字
#divider                                     // 极浅横线
```

**选色按内容类型，不要按好看**：讲结论/证明用蓝，讲术语/定义用青绿，
讲例题/练习用琥珀，提醒易错用紫。类型和色相的对应关系全篇固定，
读者才能靠颜色建立预期。

## 6. 深色主题

用户明确要深色时，`#show: scholia.with(theme: "dark")` 即可，**不要**给
`use-palette`（它是浅色调色板，会覆盖 dark）。深色下 `tint()` 会自动把强调色按 16%
混向深底色，块状区域本身就不刺眼，视觉预算可以放宽一点。

## 7. 中文排版

scholia 包装器写死了 `lang: "en"` **和 `justify: true`**。中文要加两行：

```typst
#set text(lang: "zh")
#set par(justify: false)
```

- `lang: "zh"`：改断行/断词规则。
- `justify: false`：**这条才是解决字距被拉开的**。包装器默认两端对齐，
  短行中文会被强行拉开字间空隙，读起来像散架；实测加上 `justify: false` 才恢复正常，
  只加 `lang: "zh"` 不够。

两行都放在 `#show: use-palette` 之后（show 规则按书写顺序生效，后写的覆盖先写的）。
行距、段距、缩进等数值见 [`typography-spec.md`](typography-spec.md) §3，不要在这里重复。

字体不用在底稿里配：两条链路默认都用随包的 `Notes Kai SC` / `Notes Serif SC`
（见 `typography-spec.md` §1）；`fonts:` 覆盖进不去 `note` / `sidenote` /
`label-it`，这些已由 vendored `default-fonts` 统一。
